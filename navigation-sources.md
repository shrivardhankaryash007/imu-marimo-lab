# IMU navigation: free source map

Curated public sources for a practical lesson sequence on IMU navigation. Prefer the primary docs and code below; use VectorNav for a cohesive conceptual spine and the open implementations for reproducible exercises.

## Teaching sequence and reusable material

| Topic | Source | Teaching/reuse value |
|---|---|---|
| Frames, attitude, strapdown integration, filtering and control | [VectorNav Inertial Navigation Primer](https://www.vectornav.com/resources/inertial-navigation-primer) | Free, organized chapter set: reference frames, attitude representations/transforms, attitude and position integration, Kalman filtering, nonlinear filtering, feedback control, error budgets and examples. Best overview/reference; vendor-authored, so pair estimator claims with open code. |
| Rotation/frame-convention exercises | [SciPy `Rotation`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.html), especially [`apply`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.apply.html), [`*` composition](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.__mul__.html), and [`from_quat`](https://docs.scipy.org/doc/scipy/reference/generated/scipy.spatial.transform.Rotation.from_quat.html) | Free Python implementation for vector rotation, quaternion/matrix/Euler conversion and composition. Have learners name source and destination frames and test inverse/round-trip cases; the docs define composition and application semantics. |
| Strapdown mechanics, coning/sculling | VectorNav [attitude and position integration](https://www.vectornav.com/resources/inertial-navigation-primer/math-fundamentals/math-coning) | Derivation-oriented material; use to motivate why integrating sampled angular rates and specific force is not just naïve independent scalar integration. |
| Propagation, covariance and error-state consistency | [OpenVINS IMU propagation derivations](https://docs.openvins.com/propagation), [analytical propagation](https://docs.openvins.com/propagation_analytical.html), [discrete propagation](https://docs.openvins.com/propagation_discrete.html) | Detailed equations, Jacobians and implementation-oriented derivations; excellent bridge from mechanization to an EKF. OpenVINS provides source code and tutorials. |
| Observability and estimator consistency | [OpenVINS First-Estimate Jacobians](https://docs.openvins.com/fej.html) | Explains unobservable directions and why naïve EKF linearization can create spurious information/overconfidence. Pair with its propagation docs and a hands-on motion-degeneracy exercise. |
| AHRS / practical complementary fusion | [x-io Fusion](https://github.com/xioTechnologies/Fusion) | Public C library, Python examples, and documented AHRS blending gyro with accelerometer/magnetometer feedback. Supports NWU/ENU/NED conventions and rejection/startup options. README identifies this as the maintained successor to the older Open-Source-AHRS repository. Good executable low-complexity fusion example, distinct from a full position INS. |
| EKF fusion, aiding, outages, lever arms and control outputs | [PX4 EKF2 guide](https://docs.px4.io/main/en/advanced_config/tuning_the_ecl_ekf), [controller diagrams](https://docs.px4.io/main/en/flight_stack/controller_diagrams), and [GNSS-degraded/dead-reckoning guide](https://docs.px4.io/v1.18/en/advanced_config/gnss_degraded_or_denied_flight) | Free production estimator docs/code and flight logs. Shows sensor aiding choices, innovation checks, IMU/body position offsets, dead-reckoning behavior, and how estimates feed controllers. PX4 explicitly notes output states are adjusted for IMU/body offset; board mounting docs give a concrete CoG example. |
| Rigid sensor offsets / temporal-spatial calibration | [Kalibr camera-IMU calibration](https://github.com/ethz-asl/kalibr/wiki/camera-imu-calibration), [YAML formats](https://github.com/ethz-asl/kalibr/wiki/yaml-formats) | Free calibration tooling and config examples for spatial and temporal camera/IMU relationships. Useful to teach that a transform includes both orientation and translation, and that timestamp offset is part of sensor alignment. This is camera-IMU calibration, not a general-purpose IMU-to-CoG lever-arm estimator. |
| Intro lecture and navigation context | MIT OCW [Navigation Sensors and Systems](https://ocw.mit.edu/courses/2-017j-design-of-electromechanical-robotic-systems-fall-2009/resources/mit2_017jf09_navigation/) and [Inertial Instruments and Inertial Navigation](https://ocw.mit.edu/courses/16-07-dynamics-fall-2009/resources/mit16_07f09_lec31/) | Free lecture slides/notes covering frames, dead reckoning, inertial sensors, platforms and applications. Good pre-read or lesson framing before implementation details. |
| Public data for algorithm exercises | [EuRoC MAV dataset (ETH ASL)](https://projects.asl.ethz.ch/datasets/euroc-mav/), plus [OpenVINS supported datasets/tutorial](https://docs.openvins.com/gs-datasets.html) | Freely downloadable synchronized camera/IMU recordings with ground truth and calibration. Strong for aiding/fusion and trajectory evaluation; it is visual-inertial data, not a standalone IMU-only benchmark. OpenVINS documents dataset use. |

## Suggested hands-on arc

1. **Frames first:** define sensor/body/navigation frames and active transform direction; use SciPy to rotate gravity and a forward vector through known 90° cases, inverse transforms and quaternion composition. Explicitly state ENU/NED/NWU and quaternion component order.
2. **Strapdown and drift:** integrate gyro to orientation, rotate measured specific force into navigation coordinates, add the gravity convention consistently, then integrate velocity and position. Compare a stationary trace and a short known-motion trace; explain why bias errors grow rapidly in position.
3. **Lever arm:** draw IMU, vehicle reference point/CoG and aiding sensor; write the rigid position transform and velocity correction for a rotating body. PX4 docs/code give a real estimator example; teach acceleration at a displaced point as including tangential and centripetal terms (`alpha × r` and `omega × (omega × r)`) when modeling raw accelerometer readings.
4. **Aiding and observability:** add a low-rate position/velocity or heading observation to fast inertial propagation; inspect innovations and covariance. Contrast gyro+accel tilt observability with yaw ambiguity absent a heading aid, then use OpenVINS to show visual-inertial global translation/yaw gauge freedoms and motion-dependent degeneracy.
5. **Control and outage behavior:** follow PX4's estimate-to-controller diagrams; compare aided operation with GNSS loss/dead reckoning and discuss uncertainty growth and limits. Do not present dead reckoning as bounded indefinitely.
6. **Evaluate:** run OpenVINS on a short EuRoC sequence or construct a small synthetic trajectory first; compare position/attitude error, frame alignment, timing, sensor offsets, and drift. Synthetic truth isolates algorithm/convention bugs before dataset complexity.

## Caveats for lesson authors

- No single convention is universal. State frame handedness, axis directions, transform direction, gravity sign, units, quaternion order and whether acceleration means specific force at every interface.
- Lever-arm correction depends on which point's state is represented and which point a measurement observes. Position correction alone does not correct velocity during rotation; use the estimator's stated model rather than assuming a generic sensor offset parameter covers every term.
- Observability is sensor- and motion-dependent. A filter returning a number does not mean the quantity is observable; treat unobservable global gauges as gauge freedoms, not ordinary sensor error.
- Reuse note: all links above are public educational docs, source repositories or datasets. Check each repository/data license and attribution requirements before copying code, figures or dataset files into redistributed lesson material; linking and writing an original explanation is the simplest reuse path.
